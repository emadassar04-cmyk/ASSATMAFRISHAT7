# تقرير المرحلة 2 — الطلبات والدفع والتدقيق

> الحالة: **مكتملة جزئياً بقرار صاحب المشروع**: إشعارات n8n/تلجرام مؤجَّلة. لا ننتقل للمرحلة 3 قبل موافقة صريحة.

## ما أُنجز
**نموذج الدفع والتوصيل (قرار صاحب المشروع):** الدفع والتوصيل يُتفق عليهما مع الزبون عبر واتساب أو فيسبوك بعد تقديم الطلب. لذلك: طريقة دفع افتراضية «الاتفاق»، ومنطقة توصيل «بالاتفاق» تُحدَّد رسومها من الإدارة بعد الاتفاق، ويمكن إضافة مناطق بأسعار ثابتة أو تعطيل التوصيل من الإعداد.

| المجال | التفاصيل |
|---|---|
| الزبون | سلة محلية، `/checkout`، `/orders/[id]` (أزرار واتساب/ماسنجر)، «طلباتي»، إلغاء قبل التأكيد |
| الطلبات | `create_order` (السعر والمخزون والتوصيل من القاعدة)، `set_order_status` بمخطط انتقالات، `cancel_my_order`، `set_delivery_fee`، `submit_payment`، `review_payment` |
| طلب التفصيل | `/custom-order` مع حتى 3 صور (فحص المحتوى الفعلي، bucket خاص)، تسعير وعربون من الإعدادات، حالات التنفيذ |
| الإدارة | `/dashboard/orders` و`/dashboard/custom-orders` (تغيير الحالة، الرسوم، الدفعات، صور/إيصالات بروابط مؤقتة، تواصل واتساب) |
| التدقيق | `audit_log` غير قابل للتعديل/الحذف/التفريغ، triggers على 13 جدولاً، قيم قديمة/جديدة، فاعل/دور/فرع، علامة «حساس» |
| المدقق | `/dashboard/audit` فلاتر + تصدير CSV، قراءة فقط، 2FA |
| الموثوقية | `outbox_events` بمفاتيح idempotency، تُكتب في نفس معاملة الحدث |
| الربط | صفحة `/dashboard/integrations` لواتساب للأعمال وفيسبوك، الأسرار في Vault |

## ثغرات وجدها الفحص وأُصلحت
- الخيار الافتراضي يتكرر عند إعادة استيراد ملف مُصدَّر (`matchVariant`).
- تعديلات جدول الفروع لا تُسجَّل بمعرّف الفرع في التدقيق (`audit_branch_id`).
- تصدير المنتجات يُقتطع بصمت عند 1000 صف.
- ملف E2E كان مرتبطاً بأسماء بيانات تجريبية.

## مؤجَّل / غير منجز (بالتفصيل)
1. **إشعارات n8n/تلجرام:** مُرسِل الـ Outbox (Cron) وربط n8n وتنبيه الأحداث الحساسة < 30 ثانية وإشعار الزبون وتوقيع Webhooks. **ينتظر:** token بوت تلجرام ومعرّف المجموعة واتصال n8n.
2. **واجهة رفع الإيصال للزبون:** الدالة والمخزن والمراجعة في الإدارة جاهزة ومُختبرة، لكن الواجهة لم تُبنَ لأن الدفع بالاتفاق.
3. **E2E لمسار الطلب الكامل بجلسة مسجّلة:** غير مؤتمت (الدخول عبر Google). فُحص مسار القاعدة بعمق، والواجهة يدوياً (طلب التفصيل بصورة نجح على الإنتاج).
4. **الخصومات على الطلبات:** العروض (`offers`) للعرض فقط؛ لا تُطبَّق على سعر الطلب بعد.
5. **لوحة الزبون:** المفضلة لم تُبنَ بعد.

## ملاحظة تشغيلية
- اختبارات SQL تُشغَّل بجلسة واحدة (psql أو Supabase MCP). **لا تعمل في SQL Editor بالمتصفح** (لا يُبقي الجداول المؤقتة بين الأوامر).
- لتفعيل أزرار واتساب/ماسنجر: أدخل الرقم والرابط في الإعدادات أو من صفحة الربط.
- يجب أن يبقى «Anonymous sign-ins» مطفأً في Supabase Auth.
