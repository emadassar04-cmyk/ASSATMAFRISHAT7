# وثيقة المشروع (PRD) — مفروشات العصار

> هذا هو المرجع الأساسي للمشروع في كل الجلسات. أي تعارض بين أي ملف آخر وهذه الوثيقة يُحسم لصالح هذه الوثيقة، وأي تغيير عليها يتم بموافقة صريحة من صاحب المشروع.

━━━━━━━━━━━━━━━━━━━━
## 1. نظرة عامة
━━━━━━━━━━━━━━━━━━━━
- اسم المتجر: مفروشات العصار
- المجال: مفروشات وأثاث.
- الفروع: فرعين حالياً (عدد الفروع ديناميكي ويُضاف فرع جديد من لوحة الإدارة):
  • فرع دير البلح
  • فرع النصيرات
- الجمهور: سكان قطاع غزة
- اللغة: عربي فقط (RTL بالكامل)
- مرحلة التنفيذ الحالية: MVP. التصميم مبدئي ونظيف، وسيُطوّر لاحقاً لتصميم فاخر.
  لذلك ابنِ نظام تصميم (Design Tokens: ألوان، خطوط، مسافات، زوايا، ظلال) قابلاً للتغيير بسهولة من مكان واحد.
- كل بيانات المتجر قابلة للتعديل من لوحة الإدارة وغير مكتوبة في الكود:
  الاسم، اللوجو، الألوان، الفروع، الأقسام، بيانات الدفع، السياسات، أوقات الدوام، ونصوص البوت.

### الأقسام والخصائص (ديناميكية بالكامل)
- الأقسام غير مكتوبة في الكود. يديرها المشرف والإداري من لوحة التحكم:
  إضافة / تعديل / حذف / إخفاء / ترتيب بالسحب / أقسام فرعية / صورة وأيقونة لكل قسم.
- الأقسام المبدئية (Seed Data) للتجربة فقط: كنب، غرف نوم، سفرة، ستائر، تنجيد.
- خصائص المنتج ديناميكية أيضاً: الألوان والخامات والمقاسات يضيفها المشرف،
  ولكل خيار سعر وتوفر خاص (Product Variants).

## 2. سياق قطاع غزة (إلزامي)
━━━━━━━━━━━━━━━━━━━━
- الإنترنت ضعيف ومتقطع: الموقع خفيف جداً، والصور WebP مضغوطة مع Lazy Loading، وبدون مكتبات ثقيلة غير ضرورية.
- أغلب الزبائن على الجوال: Mobile-First بالكامل.
- PWA قابل للتثبيت على الجوال، مع كاش للصفحات الأساسية.
- العملة: شيكل (₪).
- الأسعار والتوفر يتغيران بسرعة: لكل منتج حالة (متوفر / كمية محدودة / نفذ / حسب الطلب)،
  ولكل فرع مخزونه الخاص من كل منتج.
- لا يوجد توصيل حالياً: الاستلام من الفرع فقط، والزبون يختار الفرع عند الطلب.
  صمّم قاعدة البيانات بحيث يمكن إضافة التوصيل (مناطق وأسعار) لاحقاً دون إعادة بناء.

━━━━━━━━━━━━━━━━━━━━
## 3. الدفع
━━━━━━━━━━━━━━━━━━━━
- طرق الدفع: بنك فلسطين، محفظة PalPay، جوال باي.
- لا يوجد ربط API مع البنوك: الدفع يدوي.
  1. الزبون يختار طريقة الدفع، فتظهر له بيانات التحويل (من إعدادات لوحة الإدارة).
  2. يرفع صورة إيصال التحويل.
  3. يصل إشعار للإدارة، فتؤكد الدفع أو ترفضه من لوحة التحكم.
  4. يصل للزبون إشعار بحالة طلبه على نفس القناة التي طلب منها.
- خيار "دفع عربون" للطلبات المفصّلة (قابل للتفعيل والتعطيل من الإعدادات، مع تحديد النسبة).

━━━━━━━━━━━━━━━━━━━━
## 4. التصميم
━━━━━━━━━━━━━━━━━━━━
- عصري، جذاب، احترافي، يليق بمتجر مفروشات (إحساس بالراحة والدفء والفخامة).
- ألوان مقترحة قابلة للتعديل: بيج/أوف وايت + بني خشبي + لمسة ذهبية.
- الخط: عربي حديث (IBM Plex Sans Arabic أو Tajawal).
- صور المنتجات بنسبة موحدة، ومعرض صور لكل منتج مع تكبير.
- حركات خفيفة فقط (hover، انتقالات ناعمة) دون التأثير على الأداء.

## 5. صفحات الموقع (الواجهة العامة)
━━━━━━━━━━━━━━━━━━━━
1. الرئيسية: Hero، الأقسام، العروض الحالية، الأكثر طلباً، الفروع، وأزرار تواصل (فيسبوك، واتساب، تلجرام).
2. الأقسام والمنتجات: فلترة حسب القسم والسعر والفرع والتوفر، مع بحث.
3. صفحة المنتج: صور، وصف، مقاسات، خامات وألوان متاحة، السعر حسب الخيار، والتوفر بكل فرع.
   وأزرار: "أضف للسلة" / "اسأل عن المنتج بالشات" / "اطلب عبر واتساب" / "اطلب عبر تلجرام".
   مع ملخص قصير لسياسة الاستبدال.
4. طلب تفصيل: نموذج لطلب قطعة حسب المقاس والخامة واللون، مع رفع صورة مرجعية.
5. السلة وإتمام الطلب: اختيار الفرع، وطريقة الدفع، ورفع الإيصال، والموافقة على سياسة الاستبدال (Checkbox).
6. العروض.
7. الفروع: العنوان، ساعات الدوام، خريطة، رقم تواصل.
8. من نحن + تواصل.
9. سياسة الاستبدال + شروط الطلبات المفصّلة.
10. سياسة الخصوصية + شروط الاستخدام + تعليمات حذف البيانات (مطلوبة من Meta).
11. تسجيل الدخول برقم الجوال.

━━━━━━━━━━━━━━━━━━━━
## 6. لوحات التحكم (4 أدوار)
━━━━━━━━━━━━━━━━━━━━
استخدم Supabase Auth + Row Level Security لفصل الصلاحيات بشكل صارم.

أ) لوحة الزبون (Customer):
   - طلباتي وحالة كل طلب (جديد / بانتظار تأكيد الدفع / مؤكد / قيد التجهيز / جاهز للاستلام / مستلم / ملغي)
   - رفع إيصال الدفع
   - طلبات التفصيل الخاصة بي
   - المفضلة
   - بياناتي

ب) لوحة مشرف الصفحات (Moderator):
   - إدارة الأقسام والأقسام الفرعية (إضافة / تعديل / حذف / إخفاء / ترتيب)
   - إدارة المنتجات والخصائص والصور والأسعار والتوفر لكل فرع
   - إدارة العروض
   - استيراد وتصدير المنتجات (Excel/CSV)
   - تجهيز منشورات فيسبوك وتلجرام وإرسالها للموافقة
   - الرد على المحادثات المحوّلة للموظف (Unified Inbox)
   - لا يرى الإحصائيات المالية ولا الإعدادات ولا سجل التعديلات

ج) لوحة الإدارة (Admin):
   - كل صلاحيات المشرف
   - إدارة الطلبات وتأكيد الدفعات أو رفضها
   - إدارة المستخدمين والمشرفين وصلاحياتهم
   - الموافقة على المنشورات أو تعديلها أو رفضها
   - رؤية سجل التعديلات (Audit Log) كاملاً
   - الإعدادات: بيانات المتجر والثيم، الفروع وساعات الدوام والعطل، بيانات الدفع، العربون، نصوص السياسات، رسائل البوت
   - الإحصائيات:
     • عدد الطلبات (يومي / أسبوعي / شهري) لكل فرع
     • الأكثر طلباً والأكثر مشاهدة
     • المبيعات حسب طريقة الدفع
     • مصدر الطلب (الموقع / فيسبوك / واتساب / تلجرام)
     • عدد المحادثات، ونسبة ما حله البوت مقابل ما حُوّل للموظف
     • متوسط وقت رد الموظفين
     • المنتجات التي نفدت أو قاربت على النفاد

د) لوحة مشرف المتابعة (Auditor):
   - دور مستقل وظيفته مراقبة سجل التعديلات (Audit Log) فقط
   - يرى كل التعديلات: من عدّل، متى، على أي منتج/طلب/سعر/إعداد، القيمة القديمة والجديدة، ومن أي فرع
   - فلترة السجل حسب: المستخدم، نوع التعديل، التاريخ، الفرع
   - تنبيه فوري على تلجرام عند التعديلات الحساسة (تغيير سعر، حذف منتج، إلغاء طلب، تأكيد دفعة)
   - صلاحية قراءة فقط (Read-Only): لا يعدّل ولا يحذف أي شيء
   - لا أحد (ولا حتى الإداري) يستطيع تعديل أو حذف السجل نفسه

━━━━━━━━━━━━━━━━━━━━
## 7. الشات بوت الذكي (AI + بشري)
━━━━━━━━━━━━━━━━━━━━
- قنوات البوت: شات داخل الموقع، تلجرام، واتساب، فيسبوك ماسنجر.
- العقل واحد لكل القنوات: AI Agent في n8n.
- يجيب فقط بناءً على بياناتنا المخزنة في Supabase (المنتجات، الخيارات، الأسعار، التوفر بكل فرع، الفروع،
  ساعات الدوام، طرق الدفع، السياسات، الأسئلة الشائعة) عبر أدوات (Tools) أو RAG على Supabase Vector.
  يمنع منعاً باتاً اختراع أي سعر أو منتج أو معلومة غير موجودة. إذا لم يجد الإجابة يعرض التحويل لموظف.
- يستطيع: الإجابة عن المنتجات، اقتراح منتجات مناسبة، إنشاء طلب، والاستعلام عن حالة طلب.
- سياسة الاستبدال: إذا سأل الزبون عن الإرجاع أو الاسترداد، يوضح بلطف أنه لا يوجد استرداد مالي،
  وأن الاستبدال متاح فقط بزيارة الفرع، ويعطيه عنوان الفروع وساعات الدوام.
- التحويل لموظف (Human Handoff):
  • عندما يطلب الزبون "موظف"، أو لا يجد البوت إجابة، أو عند الشكاوى والطلبات المفصّلة
  • يتوقف البوت عن الرد في هذه المحادثة
  • يصل إشعار للموظفين في مجموعة تلجرام داخلية
  • الموظف يرد من صندوق محادثات موحّد (Unified Inbox) في لوحة التحكم، فيصل رده للزبون على نفس قناته
  • زر "إعادة المحادثة للبوت"
- اللهجة: عربي بسيط وقريب من اللهجة الفلسطينية، مهذب ومختصر.
- كل محادثة تُحفظ في قاعدة البيانات مع القناة ورقم الزبون.

### خارج أوقات الدوام
- البوت الآلي يعمل 24 ساعة ويجيب عن المنتجات والأسعار والطلبات في أي وقت.
- إذا طلب الزبون موظفاً خارج الدوام:
  • يرد البوت: "أهلاً فيك 🌷 دوامنا انتهى اليوم، وأحد موظفينا رح يتواصل معك بكرة الساعة [وقت بداية الدوام] إن شاء الله. بتقدر تكمل أسئلتك معي هلأ."
  • تُحفظ المحادثة في قائمة "بانتظار الرد" مع وقت الطلب.
  • عند بداية الدوام في اليوم التالي: يُرسل للموظفين على تلجرام ملخص بكل المحادثات المنتظرة، مرتبة حسب الأقدم.
  • يُرسل الرد للزبون على نفس القناة التي طلب منها. في واتساب، إذا مرت 24 ساعة، يُستخدم Template معتمد.

## 8. الربط مع المنصات (n8n Workflows)
━━━━━━━━━━━━━━━━━━━━
### فيسبوك (الأولوية القصوى)
- ماسنجر: رد آلي ذكي + تحويل بشري (Meta Graph API عبر Webhook إلى n8n).
- الرد على التعليقات: عند تعليق مثل "السعر؟" أو "بكم؟" أو "خاص"، يُرد على التعليق برد قصير،
  وتُرسل التفاصيل للزبون في رسالة خاصة (Private Reply).
- النشر التلقائي مع موافقة:
  1. عند إضافة منتج أو عرض جديد، يُولّد الـ AI نص منشور جذاب + هاشتاغات
  2. يُرسل للإداري على تلجرام مع الصورة، بأزرار: ✅ موافقة / ✏️ تعديل / ❌ رفض
  3. عند "تعديل": يرسل الإداري النص الجديد، ثم يُعاد عرضه للموافقة
  4. عند الموافقة: يُنشر على صفحة فيسبوك (وقناة تلجرام اختيارياً)
  5. تُحفظ حالة المنشور ورابطه في قاعدة البيانات
- كتالوج منتجات فيسبوك متزامن مع قاعدة البيانات.
- Meta Pixel على الموقع لتتبع الزيارات والطلبات.

### واتساب
- WhatsApp Cloud API: رد آلي ذكي + تحويل بشري.
- إشعارات حالة الطلب للزبون (عبر Templates معتمدة خارج نافذة الـ 24 ساعة).
- زر wa.me في الموقع كخيار احتياطي.

### تلجرام
- قناة عروض: نشر العروض بعد موافقة الإداري.
- بوت طلبات: تصفح واستفسار وطلب + رد آلي وبشري.
- مجموعة داخلية للإدارة: إشعارات الطلبات الجديدة، الإيصالات، طلبات التحويل لموظف، موافقات النشر،
  وتنبيهات التعديلات الحساسة.

## 10. متطلبات إضافية (إلزامية)
━━━━━━━━━━━━━━━━━━━━
### متطلبات Meta
- صفحات: سياسة الخصوصية، شروط الاستخدام، ورابط/تعليمات حذف بيانات المستخدم (Data Deletion URL).
- واتساب: احترم نافذة الـ 24 ساعة. أي رسالة بعدها تُرسل عبر Message Templates معتمدة.

### الأمان
- التحقق من توقيع كل Webhook (X-Hub-Signature-256 لميتا، Secret Token لتلجرام، مفتاح سري بين الموقع وn8n).
- Rate Limiting على الشات بوت وعلى نماذج الطلب.
- رفع الإيصالات: صور وPDF فقط، بحد أقصى 5MB، وفي Bucket خاص لا يراه إلا الإدارة.
- مصادقة ثنائية (2FA) لحسابات الإدارة ومشرف المتابعة.
- Audit Log: تسجيل كل تعديل (من، متى، الدور، الفرع، القيمة القديمة والجديدة) على المنتجات
  والأقسام والأسعار والطلبات والدفعات والإعدادات والمستخدمين. السجل Append-Only.

### تسجيل الدخول
- برقم الجوال مع رمز تحقق OTP يُرسل عبر واتساب أو تلجرام (بدون SMS).

### هوية الزبون الموحدة
- ربط حسابات الزبون من كل القنوات (موقع، فيسبوك، واتساب، تلجرام) برقم الجوال،
  بحيث يرى البوت والموظف سجل الزبون وطلباته كاملاً مهما كانت القناة.

### الموثوقية
- الطلب يُحفظ أولاً في Supabase، ثم يُرسل لـ n8n. إذا فشل الإرسال تتم إعادة المحاولة تلقائياً (Retry Queue).
- لا يضيع أي طلب أو رسالة إذا توقف n8n مؤقتاً.

### الصور والبيانات
- استيراد وتصدير المنتجات عبر ملف Excel/CSV.
- [مرحلة لاحقة — لا تُنفذ الآن] ضغط الصور وتحويلها إلى WebP تلقائياً عند الرفع، مع إضافة لوجو المتجر.
  صمّم مسار رفع الصور الآن بحيث تُضاف هذه الميزة لاحقاً دون تعديل باقي النظام.

### SEO والمشاركة
- Meta Tags عربية، Sitemap، وروابط صديقة (slug عربي).
- Open Graph لكل منتج، بحيث تظهر الصورة والاسم والسعر عند المشاركة على فيسبوك وواتساب.

### سياسة الاستبدال
- المتجر يقبل الاستبدال فقط، ولا يوجد استرداد مالي نهائياً.
- الاستبدال يتم حضورياً داخل الفرع فقط، وليس عبر الموقع أو الشات.
- لا يوجد نظام طلب استبدال إلكتروني. تُعرض السياسة كنص فقط:
  • في صفحة "سياسة الاستبدال"
  • مختصرة في صفحة المنتج وصفحة إتمام الطلب
  • يجب أن يوافق الزبون عليها (Checkbox) قبل تأكيد الطلب
- نص السياسة وشروط الطلبات المفصّلة يُعدّل من لوحة الإدارة.

- متغيرات البيئة تُضاف في Vercel فقط، وليس في الكود.

### Supabase
- كل تغيير على قاعدة البيانات عبر Migrations محفوظة في الريبو (supabase/migrations). ممنوع التعديل اليدوي.
- مشروع للتطوير ومشروع للإنتاج (أو Branching).
- التوكنات الحساسة (فيسبوك، واتساب، تلجرام، AI) تُخزن مشفرة (Supabase Vault أو متغيرات بيئة)،
  ولا تظهر أبداً في الواجهة أو الـ logs.

### n8n
- كل Workflow يُصدّر كملف JSON داخل مجلد /n8n في الريبو، ويُحدّث عند أي تعديل.
- رابط n8n ثابت (دومين ثابت) لاستقبال Webhooks من الموقع وميتا وتلجرام.

## 12. مراحل التنفيذ
━━━━━━━━━━━━━━━━━━━━
لا تنتقل لمرحلة قبل أن أؤكد المرحلة السابقة:
• المرحلة 0: التأسيس والتوثيق (Schema، Workflows، CLAUDE.md، Roadmap، GitHub)
• المرحلة 1: الواجهة العامة + الأقسام والمنتجات + لوحة المشرف
• المرحلة 2: الطلبات والدفع + لوحة الزبون + لوحة الإدارة + سجل التعديلات ولوحة مشرف المتابعة
• المرحلة 3: الشات بوت + الربط مع فيسبوك وواتساب وتلجرام + النشر بالموافقة + الإحصائيات
• المرحلة 4 (لاحقاً): التصميم الفاخر + ضغط الصور واللوجو + التوصيل

### قواعد عامة لكل المراحل
- كود نظيف ومقسم، مع تعليقات بالعربي.
- استخدم placeholders واضحة بدل البيانات الحقيقية، مثل [رقم الفرع] و[رقم الحساب] و[ساعات الدوام].
- حافظ على تحديث .env.example ودليل النشر (docs/deployment.md) مع كل مرحلة.
- اكتب Acceptance Criteria واختبارات لكل مرحلة قبل تسليمها.
- لا تفترض أي شيء غير مذكور؛ اسألني قبل أي قرار مهم.
